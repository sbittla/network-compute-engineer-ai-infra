# R3 — Skill versus reasoning: model answer

**The line.** A number is evidence of *measurement skill* only if it came from *your* environment, with an
environment manifest, a stated method and repetitions (median and spread). A number computed from a model
or from supplied data is evidence of *reasoning skill*: you set up the problem and the arithmetic correctly.
Both are valuable; only the first supports a `[MEASURED]` claim (Section 24.9, evidence ladder).

**Defensible as skill.** The laptop runtime of a lab checker or a 1 GB log parse, measured over five runs
with the machine recorded, is a real `[MEASURED]` number about your laptop (Chapter 23's K7 makes the same
distinction). An L2 `ib_write_bw --use_cuda` run per rail with a manifest is stronger still.

**Defensible only as reasoning.** The Chapter 22 attribution shares, the ECMP idle-uplink estimate
(11.6 of 32), Young's interval (2,058 s) and every readiness score are `[MODELED]` or `[SIMULATED]`. In an
interview you defend the *method* (why √(2CM), why (31/32)^32), not the value.

**Where candidates fail.** Presenting an L1 simulation as "measured 38 GB/s": the lab caps that evidence at
level 1 (SIMULATION_CLAIMED_AS_MEASURED) because an interviewer who notices discounts everything else.
