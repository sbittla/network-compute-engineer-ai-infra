## Cross-scope issues (seen, not fixed)

1. `book/part-4-distributed-ai/ch12-collective-communication-nccl/manuscript.md:440` uses the
   NCCL ≤ 2.19 WARN form (`with error 12, opcode 0, len 0, …`). If the surrounding text says 2.2x, it
   should use `with status=12 opcode=0 len=0 …` or be labelled 2.18–2.19 (see the proposed fact above).
2. `book/part-5-production-operations/ch19-reliability-security-multitenancy/` (manuscript:335, lab
   `incident_toolkit.py` `NETIB_RE`) parses `NET/IB : Got completion … with status=` **and** expects a
   trailing `hca mlx…`. Real NCCL 2.23+ prints `NET/IB:` with no space before the colon, so a regex
   anchored on `NET/IB : Got completion` would not match real 2.23+ logs. The lab data is
   self-consistent; the issue is only realism. Suggest `NET/IB ?: Got completion` and accepting
   `error N,` or `status=N`.
3. `book/part-3-networking/ch07-*/review/REVIEW.md:40` says that the log line matches the NCCL form. That
   is still true for 2.18–2.19, and REVIEW files were not edited.

> **Coordinator correction (2026-10-30):** this report puts the `NET/IB:` prefix and `hca` field at 2.23+. A re-check of `net_ib.cc` at v2.22.3-1 shows both are already present in **2.22**, and ch08/ch12 were corrected to say 2.22+. See VERIFIED_FACTS.md, "IB completion WARN format".
